一、platform 场景复杂化
----------------------
目标：
- 在原 platform 场景基础上提高障碍物复杂度。
- 静态障碍物数量约增加 30%。
- 移动障碍物增加到 5 个。
- 障碍物分布尽量均匀，避免只在局部堆叠。

主要修改：
- 修改 guidance/ros_ws/src/multi_uav_formation/scenes/platform.json。
- 同步更新 guidance/ros_ws/src/multi_uav_formation/worlds/platform.world。
- 保持 JSON 场景、Gazebo world、RViz 可视化、EGO 点云输入之间的一致。
- 增加移动障碍物轨迹参数，使其在通道和关键冲突区域中形成动态避障压力。


二、障碍物膨胀和重规划频率参数整理
--------------------------------
目标：
- 明确 ego_more_obstacles.launch / platform.json 中如何调整安全距离和重规划频率。
- 为后续实验提供统一参数入口。

关键参数：
- obstacles_inflation：障碍物膨胀/安全距离。
- replan_time 或 replanning_time：EGO 重规划周期，数值越小，重规划越频繁。
- movingObstacleTimeAwareLambda：移动障碍物时间相关代价权重。

说明：
- obstacles_inflation 影响 EGO 对障碍物的安全距离判断。
- 重规划频率影响动态障碍物场景下路径更新速度。
- 安全距离过大时容易路径保守、绕行变长甚至无解；过小时容易贴障或碰撞。


三、老式提前避障：发布未来障碍物点云
----------------------------------
目标：
- 让 EGO 在动态障碍物到达当前位置之前提前做出避让。

实现思路：
- 根据移动障碍物当前状态和速度/周期预测未来位置。
- 将未来若干时刻的位置也采样为点云。
- 把这些预测点云作为普通障碍物发布给 EGO。

特点：
- 实现简单，直接复用 EGO 静态地图/点云接口。
- 不需要改 EGO 优化器内部代价函数。

问题：
- 时间信息被抹掉，未来障碍物被当成“现在就存在”。
- 容易把可通行区域过度封堵。
- 对预测步长、预测数量和点云膨胀较敏感。
- 在部分仿真中导致轨迹保守、绕行大、成功率下降。


四、新式提前避障：移动障碍物时间相关代价函数
------------------------------------------
目标：
- 不再把未来障碍物直接发布成静态点云。
- 在轨迹优化阶段，根据轨迹点对应的时间，计算移动障碍物预测位置并加入代价。

核心思想：
- 对 B-spline 控制点或轨迹采样点 q_i，估计其对应未来时间 t_i。
- 根据移动障碍物模型预测 obj(t_i)。
- 计算 q_i 与 obj(t_i) 的距离 dist。
- 若 dist 小于安全距离，则产生惩罚项并对轨迹优化梯度施加排斥。

典型梯度形式：
  Eigen::Vector3d dist_grad = (q.col(i) - obj_prid) / dist;
  gradient.col(i) += -2.0 * dist_err * dist_grad;

含义：
- dist_grad 表示轨迹点远离障碍物的单位方向。
- dist_err 表示当前距离相对安全距离的误差。
- gradient 最终进入优化器，用于调整 B-spline 控制点，使轨迹远离对应时间的移动障碍物。


五、动态避障开关与配置项
----------------------
目标：
- 可以在 JSON 中手动切换不同避障模式。
- 避免每次实验都修改 C++ 代码。

新增/整理的配置思想：
- 是否开启老式提前避障。
- 是否开启时间相关代价函数。
- 移动障碍物是否使用独立权重。
- movingObstacleTimeAwareLambda 控制动态障碍物时间相关代价强度。

实际含义：
- 不提前避障：移动障碍物主要依靠实时点云/当前障碍信息处理。
- 增加点云方法：把预测未来位置发布成障碍物点云。
- 代价函数/梯度方法：在优化器内部加入时间相关动态障碍物代价。


六、移动障碍物独立权重
--------------------
目标：
- 将动态障碍物惩罚强度从静态障碍物权重中拆出来。

新增参数：
  "movingObstacleTimeAwareLambda": 0.5

意义：
- 数值越大，轨迹越倾向于远离移动障碍物预测位置。
- 数值过小，提前避障效果不明显。
- 数值过大，轨迹可能过度弯曲、绕行、震荡，甚至找不到可行解。

原来情况：
- 移动障碍物更接近被并入普通障碍物/静态障碍物代价体系。
- 动态障碍物和静态障碍物权重耦合，难以单独调参。

现在情况：
- 静态障碍物仍由原 EGO 地图/ESDF/点云代价处理。
- 移动障碍物预测代价可由独立 lambda 控制。

九、仿真结果分析与调参方向
------------------------
主要观察：
- 老式点云预测容易过度保守，因为它把未来障碍物当成当前障碍物。
- 新式代价函数方法理论上更合理，但对预测时间、权重、梯度方向、距离阈值较敏感。
- 新式方法若使用所有预测点，可能导致多重惩罚；改成取最近预测位置后更稳定。

后续建议：
- 缩短预测时域，避免远期预测干扰当前轨迹。
- 对 movingObstacleTimeAwareLambda 做系统扫描。
- 对动态障碍物梯度做限幅，避免局部震荡。
- 将动态障碍物代价与静态障碍物 ESDF 代价明确分离。
- 加入速度方向相关权重，只对可能发生交会的障碍物加强惩罚。
