ALP 动态避障、实验与代码发布问题记录（2026-06-11 至 2026-06-28）
============================================================

本文记录近期工作中遇到的主要问题、原因判断、已采取处理方式和后续建议。


1. 老式提前避障效果不好
----------------------
现象：
- 开启“未来点云”预测后，部分仿真结果比不预测更差。
- 轨迹更保守，绕行变大，甚至出现失败。

原因：
- 老式方法把移动障碍物未来位置也发布为普通障碍物点云。
- EGO 无法知道这些点云对应未来时间，只会当成当前已经存在的障碍物。
- 结果是可通行空间被提前占满，尤其在障碍密集场景中更明显。

处理：
- 保留老式方法作为 baseline。
- 新增时间相关代价函数方法，避免简单把未来位置全部静态化。

建议：
- 老式方法只适合作为对照，不建议作为最终主方法。


2. 新式提前避障初期预测逻辑不稳定
--------------------------------
现象：
- 新式方法初期仿真结果也不理想。
- 轨迹可能出现抖动、绕行过大或动态障碍物惩罚过强。

原因：
- 移动障碍物预测位置、轨迹控制点时间、B-spline 时间尺度之间需要严格对应。
- 如果一个轨迹点同时被多个未来预测位置惩罚，会造成过度约束。
- 权重和安全距离没有独立调好时，动态代价会压过原本的平滑项和静态避障项。

处理：
- 将动态障碍物时间相关代价独立出来。
- 增加 movingObstacleTimeAwareLambda。
- 调整为取最近/最相关预测位置，减少多重惩罚。

建议：
- 继续做 lambda、预测时域、距离阈值三者的联合扫描。
- 对梯度做限幅和平滑。


3. 移动障碍物可能被重复计入代价
------------------------------
现象：
- 用户怀疑移动障碍物是否同时被作为静态障碍和移动障碍计入代价函数。

原因：
- 如果移动障碍物当前点云仍进入普通点云地图，同时新式方法又加入时间相关代价，则同一个障碍物可能同时影响静态 ESDF 代价和动态预测代价。
- 这不一定错误，但会改变等效权重。

处理：
- 解释原权重与新增独立权重的区别。
- 将 movingObstacleTimeAwareLambda 作为单独参数，便于减小或关闭动态附加惩罚。

建议：
- 最终论文/实验中应明确三种设置：
  只静态点云。
  静态点云 + 未来点云。
  静态点云 + 时间相关动态代价。
- 若要避免重复惩罚，可让动态障碍物不进入静态地图，只走动态代价。


4. 障碍物膨胀系数敏感
--------------------
现象：
- obstacles_inflation 从 0.45 降到 0.40 后结果变化明显。
- 不同膨胀距离对成功率和平滑度影响较大。

原因：
- 膨胀距离同时影响安全裕度和可行空间。
- 太大时，通道被压窄，规划器容易找不到好路径。
- 太小时，轨迹容易贴近障碍物或发生碰撞。

处理：
- 扫描 0、0.05、0.10、0.15 到 0.50。
- 每个参数多次仿真，统计成功率和平滑度。
- 实验后恢复默认 0.35。

建议：
- 后续应同时报告障碍物密度和膨胀距离，否则单一参数最优值不可泛化。


5. 重规划频率和动态障碍物周期耦合
--------------------------------
现象：
- 用户手动修改移动障碍物周期后，需要重新比较三种避障方式。
- 原参数在新周期下不一定仍然适用。

原因：
- 动态障碍物速度/周期改变后，预测误差和交会时机都会变化。
- 重规划周期太长时，轨迹无法及时响应。
- 重规划过频繁时，计算压力增大且轨迹可能不稳定。

处理：
- 在新周期下分别运行不提前避障、老式提前避障、新式提前避障。
- 统一统计成功率、耗时和平滑度。

建议：
- 将 replan_time 与移动障碍物最大速度关联。
- 可设计经验规则：障碍物越快，预测时域变短，重规划频率提高。


6. 图表格式多次调整
------------------
现象：
- 初始图表不符合展示要求。
- 用户要求去掉图名、去掉 “vs” 字样、横纵轴改中文。
- 后续又要求三种方法全部使用柱状图。

原因：
- 图表从分析工具默认样式生成，未完全按论文/汇报习惯整理。

处理：
- 去掉标题。
- 横纵轴改为中文。
- 三种方法名称统一：
  不提前避障。
  增加点云方法。
  代价函数/梯度方法。
- 对方法对比改用柱状图。

建议：
- 后续所有图保持同一字体、字号、颜色和方法命名。
- 若用于论文，建议导出矢量图或高分辨率 PNG。


7. calcMovingObjCost() 的来源与新增逻辑混淆
------------------------------------------
现象：
- 用户询问原代码中是否本身就有 calcMovingObjCost()。

原因：
- EGO/Fast-Planner 系列代码中已有一些移动障碍物预测或动态对象代价相关接口。
- 本次工作是在此基础上调整配置、权重、开关和具体代价使用方式。

处理：
- 说明新增工作不是凭空发明所有函数，而是围绕已有优化器接口做动态障碍物时间相关代价的工程接入和实验化。

建议：
- 写论文或 README 时避免表述成“首次提出整个动态障碍物代价函数”。
- 更准确的说法是：针对 ALP/MUSK-EGO 集成场景，构建可切换的时空动态障碍物惩罚机制并进行实验验证。


8. GitHub contributors 显示原 MUSK 作者
------------------------------------
现象：
- 上传后 GitHub 仍显示 xirhxq / Yang Siyuan 为 contributor。

原因：
- 初始仓库继承了 MUSK 原始 git 历史。
- GitHub contributors 依据历史提交作者统计，而不是只看当前文件内容。
- 即使强制推送干净历史，页面统计也可能缓存。

处理：
- 将 main 改成新的无父根提交。
- 作者和提交者设置为 BobPurespecius。
- 检查远程只有 refs/heads/main 指向干净提交。
- 建议必要时删除 GitHub 仓库，重新创建空仓库，再推送干净历史。

建议：
- 新仓库不要从原 MUSK fork。
- 不勾选 README/LICENSE/.gitignore，保持空仓库。
- 从本地干净 main 执行普通 git push。


9. GitHub Personal Access Token 推送问题
--------------------------------------
现象：
- 命令行推送时报：
  fatal: could not read Username for 'https://github.com'

原因：
- 当前终端环境没有可交互输入 GitHub 账号和 token。
- GitHub 不再接受账号密码作为 HTTPS 推送密码。

处理：
- 指导用户创建 GitHub Personal Access Token。
- 推送时用户名填 BobPurespecius，密码位置粘贴 token。

建议：
- 只给 ALP 仓库 Contents: Read and write 权限。
- token 不要写入代码、README 或聊天截图。


10. README 修改后 GitHub 看不到变化
----------------------------------
现象：
- 用户修改 README.md 后，GitHub 页面未变化。

原因：
- 当时 README.md 只是本地 modified，还没有 commit/push。
- 不是 GitHub 缓存问题。

处理：
- 检查 git status，确认是 M README.md。
- 说明普通 README 修改只需：
  git add README.md
  git commit -m "Update README"
  git push

建议：
- 只有重写历史时才使用 --force-with-lease。
- 普通代码/文档更新使用普通 git push。


11. 本地包很大但 GitHub 上传包较小
--------------------------------
现象：
- 本地 /home/bob/ALP 约 2.4G。
- GitHub 上传包约 26M。
- 用户担心是否漏传全部代码，因为原 EGO 就有约 24M。

原因：
- 本地 2.4G 包含 data、analysis、build、devel、logs、debug_logs 等被忽略内容。
- GitHub 上传的是 Git 跟踪文件，不包含这些本地生成物。
- EGO 已跟踪内容约 585 个文件，实际约 32M，压缩后约 26M 属正常范围。

处理：
- 使用 git status --ignored 检查没有未跟踪代码遗漏。
- 使用 git ls-files 统计已跟踪文件。
- 确认 ego-planner 不是 submodule，而是源码文件进入仓库。

建议：
- 后续新增代码后先看 git status。
- 若出现未跟踪源码目录，应手动 git add；若是数据/构建产物，应继续忽略。


12. 旧历史备份分支可能造成心理干扰
--------------------------------
现象：
- 本地保留 backup/pre-clean-history-20260626。
- 该分支中有原 MUSK 历史作者。

原因：
- 重写 main 前为了安全创建了本地备份分支。
- 它没有推到 GitHub，但本地 git log --all 会看到旧作者。

处理：
- 说明它不影响远程 main。
- 若确认不再需要，可执行：
  git branch -D backup/pre-clean-history-20260626

建议：
- 删除备份分支后可运行 git gc 清理本地对象。
- 删除前确认不需要找回旧历史。


13. 论文创新性仍需加强
--------------------
现象：
- 用户询问当前创新距离发论文还有多远。

判断：
- 当前已经有工程集成、动态避障机制、参数实验和可视化结果。
- 但若作为论文核心贡献，还需要更系统的方法定义和实验。

主要短板：
- baseline 不够多。
- 场景数量有限。
- 动态障碍物预测模型较简单。
- 消融实验还不完整。
- 权重和参数选择缺少理论或经验规则支撑。

建议：
- 将方法包装为“B-spline 轨迹优化中的时空动态障碍物风险场/时间相关代价”。
- 增加不同障碍密度、速度、周期、预测窗口和权重的消融实验。
- 与不预测、未来点云法、原 EGO 静态避障进行系统比较。
- 报告成功率、碰撞率、耗时、路径长度、速度/加速度/jerk 平滑度。
