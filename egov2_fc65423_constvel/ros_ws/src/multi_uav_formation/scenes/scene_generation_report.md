# Event-Generated ALP Benchmark Scenes

## Scope

This experiment adds three independent scenes without changing EGOv2, MINCO,
candidate thresholds, moving-object cost, or the existing C2 forest scene.
The scenes are generated by `scripts/generate_event_scenes.py`.

## Data Sources

* Base scene: `scenes/long_cylinder_forest.json`.
* Observed trajectory: `/tmp/v2_C2_visibility_run1_trajectory.csv`.
* Observed risk/candidate evidence: `/tmp/v2_C2_run1.log`.
* The trajectory CSV contains target position, each UAV position, and measured
  moving clearance at the same timestamps.

The generator selects the observed target sample nearest each requested route
 x-coordinate. It does not sample random phase or amplitude values.

## Parameter Derivation

For a selected conflict time `t_c`, target position `(x_c, y_c)`, amplitude
`A`, period `T`, and desired offset `d` at the conflict:

```text
A sin(2*pi*t_c/T + phase) = d
phase = asin(d/A) - 2*pi*t_c/T
```

The positive-velocity branch is used for crossing events so the obstacle leaves
the nominal path after the encounter. The generator also computes static
clearance at `y_c-0.8`, `y_c`, and `y_c+0.8`; unsafe late-route candidates were
removed before generating the final files.

The scene JSON records `eventDerivation` for every obstacle, including the
source sample time, target position, static side clearances, expected type,
and derived phase. These are geometric recommendations, not claimed planner
outcomes.

## Generated Files

* `event_generated_spatial.json`
* `event_generated_temporal.json`
* `event_generated_mixed.json`
* `event_generated_recommendations.json`
* `../worlds/event_generated_spatial.world`
* `../worlds/event_generated_temporal.world`
* `../worlds/event_generated_mixed.world`

Each scene has three moving cylinders and retains the original static forest,
map size, target waypoints, and UAV initialization.

## Classification

Classification is event-level and uses runtime logs:

* Spatial: best side improvement `>= 0.10 m`, temporal optimized improvement
  `< 0.05 m` (or unavailable).
* Temporal: both side improvements `< 0.05 m`, temporal optimized improvement
  `>= 0.10 m`.
* Mixed: best side improvement `>= 0.10 m` and temporal optimized improvement
  `>= 0.10 m`.
* Low-information: all other cases, including failed/missing candidate data.

## Validation

Each scene was run three times headless with the same planner parameters. Each
run was a roughly 60-second short validation run and ended through the normal
external timeout teardown. Empty logs from an earlier malformed ROS master URI
were discarded and are not counted.

| Scene | Runs | Triggered | Spatial | Temporal | Mixed | Low-information | Zero-clearance |
|---|---:|---:|---:|---:|---:|---:|---:|
| event_generated_spatial | 3 | 353 | 62 | 8 | 0 | 283 (80.2%) | 0 / 16542 (0.000%) |
| event_generated_temporal | 3 | 247 | 17 | 11 | 0 | 219 (88.7%) | 50 / 16560 (0.302%) |
| event_generated_mixed | 3 | 326 | 44 | 6 | 0 | 276 (84.7%) | 28 / 16569 (0.169%) |

The spatial scene produced at least 10 spatial events in every run. The
temporal scene did not produce at least 10 temporal events in any single run,
and its events were not spatially neutral. The mixed scene produced zero Mixed
events.

All nine valid runs had:

* process death: 0;
* `bad_array` / double-free: 0;
* at least two dynamic obstacles contributing events;
* at least two UAVs contributing events;
* `SIDE_PLUS`, `SIDE_MINUS`, and `TEMPORAL` selections observed across the
  scene groups.

## Conclusion

The event-driven generator is valid as a reproducible scene-construction and
diagnostic workflow. It successfully ties obstacle phase to observed target
conflict time and rejects static-map unsafe placements.

However, the requested high-quality acceptance criteria are not met:

* Spatial scene: spatial mechanism is observable, but low-information remains
  high and temporal candidates also appear.
* Temporal scene: temporal improvement is too infrequent and spatial effects
  are not below the required neutral threshold.
* Mixed scene: no event satisfies both measured improvements.

Therefore these scenes are not a formal benchmark yet. The remaining gap is
algorithm/runtime behavior after initialization, especially MINCO and temporal
candidate success, rather than an absence of a deterministic event-generation
rule. No planner changes were made in this task.
